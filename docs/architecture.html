What runs when you open a recipe?

The visualizer’s CLI reads the JSON file, calls json.loads, and passes the resulting dictionary into render_recipe. Only after rendering succeeds does main() create the output directory and write the HTML string.

compile_recipe loads the schema, checks the schema itself and creates a Draft 2020-12 validator with a format checker. It collects every input error with its JSON path. Any error raises ValueError before graph construction begins.

The second validation also protects callers that supply an already compiled graph directly to render_graph, including the meal-merge experiment. Renderer entry points · Compiler entry points · Meal-merge caller

Watch build_graph replace references with edges

The function copies recipe metadata and initializes nodes and edges. The ingredient loop copies declared totals; the step loop compiles every authored action, including measurement.

Ingredient loop · copy the total oil

The recipe declares neutral_oil as 7 tsp total. Its explicit measure_neutral_oil step produces three purpose-specific states: 1 tsp for the marinade, 1 tbsp for searing beef, and 1 tbsp for searing onions.

The ingredient loop emits only the total ingredient node. The step loop emits the authored measurement action and its output states, preserving its 60-second estimate and measuring-spoon requirement. Validation checks that 1 + 1 × 3 + 1 × 3 = 7 tsp; compilation does not invent the total or measurement details.

Step loop · consume the oil portion

For sear_onions, the compiler copies the instruction, operation, resources, duration and dependsOn into an action record. It removes the nested input and output fields. Each input ID becomes the source of an edge into the action. Each output definition becomes a new state node and an edge out of the action.

These edges contain IDs, so a producer can appear later in the file. Reference resolution happens after both loops. The required earlier sear stays in dependsOn on the action record.

Why the validator builds two kinds of adjacency

Index the food graph

validate_graph builds an ID dictionary. If it shrinks the node count, an ID was reused. It then allocates incoming[id] and outgoing[id] as sets of neighboring IDs, checking that each edge has known endpoints and connects permitted node types.

For sear_onions, the incoming set is {onion_wedges, onion_searing_oil} and the outgoing set is {seared_onions}. The validator can now count producers and consumers. Every food state needs one producer, each unfinished food node needs one consumer, and terminal outputs need zero consumers.

Detect cycles, then trace the food backward

For the cycle check, it copies outgoing into adjacency and adds (dependency, action) pairs. Kahn’s algorithm repeatedly pops zero-indegree nodes from a deque and decrements their successors’ indegrees. If the visit count falls short, a cycle remains.

The final traversal starts at graph['outputs'] and follows only the original incoming sets. This distinction matters: ordering one action before another cannot demonstrate that its food reaches the plate.

How action_order picks the next action

The viewer needs a list of actions. action_order first indexes every action-produced state by its producer. When it finds the edge onion_wedges → sear_onions, the producer map resolves onion_wedges to prep_onions. It does the same for the measured oil, then combines these producers with the action’s explicit prerequisites.

followers reverses this lookup. Popping an action removes its ID from each follower’s prerequisite set. When that set empties, the follower enters a min-heap keyed by its position in the compiled action list. Measurements were appended first, so ready measurements win ties with ready authored steps.

From Python dictionaries to a selected SVG node

Write the two payloads

render_graph splits the shared template once at each placeholder and inserts the bundled Dagre library and license, the graph, and the action ID list. embedded_json escapes angle brackets and ampersands so recipe text containing a closing script tag survives the HTML parser. Both payloads go into application/json script elements.

Lay out the graph

The template’s JavaScript creates connections from the food edges, then appends an order connection for each dependsOn entry. draw() gives Dagre node sizes and named edges, weighted 3 for food and 1 for ordering. It uses the resulting coordinates to create SVG groups and paths. The ordering toggle calls highlight(), which changes visibility without rerunning layout.

Trace one press of Next

Suppose the viewer is on sear_beef. The Next handler calls goToStep(stepIndex + 1). That function clamps the index and calls select(steps[stepIndex], true). In this recipe the selected ID is now sear_onions.

syncStep() updates the count, instruction and navigation buttons. highlight() updates SVG classes and accessibility attributes. select() rebuilds the detail panel, looking up food neighbors in recipe.edges and ordering neighbors in dependsOn and connections. Finally focusNode() sets the scale to 1 and translates the viewport to center the selected node.

Explore mode allows any node to be selected while preserving stepIndex. Returning to step mode restores that position. These interactions run entirely in the generated HTML.

Where the accepted decisions show up in code

001 · Graph representation. The node type and directed from/to records give the validator enough information to check that an action transforms food. Intermediate states also let the viewer identify exactly which output an action consumes.

002 · Separate authoring from compilation. The input contract exposes ingredients and steps. The step loop compiles their references; assigning priority in the viewer affects tie-breaking only. An author can reorder independent steps without creating new dependencies. Shared ingredient keys and structured operation names carry information a future planner could use.

007 · Explicit measurement and ingredient totals. Supersedes the generated measurements of 003 and 006. Ingredients declare recipe totals, and authors write measure steps with quantified outputs. The compiler preserves those declarations, and the validator checks that each measurement conserves the ingredient identity and amount. Meal optimization only combines actions matching its conservative template; custom measurements remain separate.
